## Unreleased

### Added

- macOS release binaries are now Developer ID signed and notarized ([`docs/macos-code-signing.md`](docs/macos-code-signing.md)). Zig emits an ad-hoc linker signature with no team identifier, which made keychain access lists bind to the code hash — so "Always Allow" could never survive a rebuild or an update — and made a browser-downloaded tarball unrunnable under Gatekeeper. `scripts/sign-macos.sh` imports the certificate into a temporary keychain, signs with the hardened runtime and a secure timestamp, verifies, and restores the keychain search list; `scripts/notarize-macos.sh` submits the signed binaries, prints Apple's log on rejection, and re-checks a quarantined copy through `spctl`. Both run in `release-binaries.yml` between build and packaging, so the tarball, the checksum and the `@makai/cli-darwin-*` npm payload ship the same signed bytes, and a tag build fails rather than publishing unsigned macOS binaries. `make sign` applies the same signature to a local build, which is what ends the per-rebuild keychain prompt during development. A bare executable cannot carry a stapled ticket, so Gatekeeper resolves notarization online on first run; that limit and the `.pkg`/`.dmg` alternative are documented.

### Fixed

- Rewrote the TUI's inline terminal renderer (vendored `zigzag` `Program`, `zig/src/tui/app.zig`): the live frame is now a cursor-relative region painted with print-above history, replacing the bottom-anchored frame plus scroll-region insertion that left stale copies of the composer and status bar in the terminal whenever the frame shrank (closing the model picker or finishing a turn) and overwrote visible history when it grew. Full-width panel borders no longer lose their last column, `/clear` clears the screen and scrollback, quitting erases the live widgets and leaves only the transcript, streamed reasoning renders before the answer instead of after it, and window resizes are debounced and answered with a relayout (stale screen scrolled into scrollback, visible history tail reprinted at the new width) instead of a cursor-relative repaint over reflowed rows. The inline frame is now a bottom-anchored window over the transcript row stream: opening the model, permissions, session or approval panel covers the history tail instead of scrolling it away, and closing it puts the composer back on the bottom row without leaving blank rows or duplicating scrollback. Paints rewrite only the rows that changed, so a spinner tick costs one or two rows instead of a screen. The PTY harness gained a VT screen model and judges tool rows, steer echoes and approval prompts by what is on screen rather than by repaint bytes. Long system rows such as the OAuth login prompt wrap instead of being cut with an ellipsis, and URLs in them are OSC 8 hyperlinks that stay one link across wrapped rows. While the TUI runs, stderr is redirected to `~/.makai/tui-stderr.log` so stray library prints (for example the OAuth proxy warning during login) can no longer shift the cursor and leave stale rows on screen. the macOS keychain item is now labeled "makai credentials" and the `auth.json` item migrates to `auth.shared.json` on first read (unsigned dev builds still get one keychain prompt per new binary because access lists bind to the code hash; signed releases are keyed by team ID and keep "Always Allow"); `MAKAI_KEYCHAIN_SERVICE` isolates keychain items for tests; `/login` shows which providers are logged in, hold an API key, or have expired; and the model catalog lists Anthropic models (live `/v1/models` fetch with cache and static fallback) whenever Anthropic credentials exist, with the status bar hiding the cost for models without a known price. Anthropic model definitions now carry the API origin as `base_url` (the provider appends `/v1/messages` itself; the TUI's default model previously doubled the path and 404'd), the provider no longer doubles a suffix already present, and non-2xx responses include the API's error type and message in the error card. The cached Anthropic catalog is reused at startup for 24 hours and re-fetched after that (stale copy kept only as a fallback), folding a catalog entry into the default model keeps that entry's output limit and context window instead of the fallback's conservative values, the catalog merge frees each model exactly once when an allocation fails midway, tool rows take their status from the linked tool entry rather than from status words that may appear in the tool's label, `/quit` inside the resize debounce erases the reflowed live region completely, `Cmd.println` still writes immediately for full-screen (non-inline) programs, `PgUp`/`PgDn` (and the mouse wheel) now scroll the inline window over the whole transcript with a `↑ SCROLL n%` row instead of doing nothing in a real terminal, and `/login` still reports `✓ env key` when the stored auth cannot be loaded. See [`docs/tui-rendering-model.md`](docs/tui-rendering-model.md).

## [0.2.0] - 2026-09-11

### Added

- Implemented gap 5 of the #204 remainder — transactional publication with exactly-once settlement (#214): the stdio host's publication paths (tool-request publication, outbox delivery, the final pipe-to-stdout drain, ordinary event publication) now settle-or-propagate exactly once — a processed terminal is never re-published, publication failures propagate instead of being swallowed, and the drain hands a frame off before advancing its read position.

- Added full client sequence control to the agent protocol's clients — the `#210` gap-7 slice series, completing the TS SDK half (#215) and the Zig client slices (#216, #218, #226, #227, #231, #232, #239, #240): clients mirror the server's per-session counter optimistically and reconcile on evidence — tracked pending sends roll back monotonically on correlated `agent_error`/`nack` rejections (an older unresolved send's floor is never lost), `duplicate_sequence` answers retire a retry's record with exactly one proven counter step (same-sequence same-payload retries only, payload-digest matched, with competing-payload and provenance-broken masks), a monotone proven floor records every sound lower bound (busy parity, all-rejected floors, settlement minimums, accepted starts) that optimistic regressions cannot erase, a bounded two-state stop probe resolves unknown send outcomes (pre-send stop, then the post-send value on a correlated `invalid_request`), and explicit-sequence send surfaces (`sendAgentMessageWithSequence`, `sendAgentStopWithSequence`, `peekNextSequence`) support recovery flows. The TUI integrates the same machinery with drain-before-sync pump ordering, ownership-guarded teardown probe drivers, ambiguous-write reconciliation (probe-stop + session-drop on an unresolvable write), and session-gone identity clearing backed by an exclusive-id registration variant (`sendAgentStartWithSessionExclusive`). Spec §13.1/§13.4.1 markers are `[current]`.

- Added the gap-7 spec/ledger reconciliation (#238/#225, closing #213 as superseded): every §13 claim in [`docs/v1-sdk-agent-provider-spec.md`](docs/v1-sdk-agent-provider-spec.md) is `[current]` against the landed slices, [`docs/oap-alignment.md`](docs/oap-alignment.md) pins ledger provenance to each merge sha, and the greppable residual catalogue (`RESIDUAL-1`…`RESIDUAL-6`, with the SSE coverage gap tracked in #242) documents the wire-unobservable ambiguities adapters must treat as documented uncertainty rather than guarantees.

- Added a Windows ARM64 release target (`aarch64-windows`): release binaries, sha256 checksums, and the `@makai/cli-win32-arm64` npm platform package join the existing five targets, completing arm64+amd64 coverage across Linux, macOS, and Windows; CI's cross-compile smoke job compiles it on every PR so regressions surface before a tag (#196 follow-up).

- Added the zero-comments policy toolchain (#228/#229; #236, #237, #241, #243): `scripts/check-no-comments.mjs` enforces zero comments across all tracked `.zig` and `.ts` sources — TypeScript scanned via the TS parser's literal spans, Zig via a state-machine lexer over string/multiline/char literals — exempting functional directives only (`// zig fmt: off|on`; TS shebangs, file-leading `@ts-check`/`@ts-nocheck`/`/// <reference>`-family only, position-independent `@ts-ignore`/`@ts-expect-error`, lint/coverage pragmas, functional `@deprecated`). Enforced by a dedicated CI job. The grandfather allowlist was retired in the same release (#243 stripped ~13.4k comment lines across 230 files) and its one-way latch (`no-comments-allowlist.txt.retired`) permanently closes re-seeding.

- Implemented gaps 4 and 6 of the #204 remainder for the agent protocol stdio host (spec §13.2.7 rule 7, §13.1/§13.3.4; issue #210, which stays open for gaps 5 and 7): **EOF-cancel for distributed-tool waits** — when `runStdioMode` observes stdin EOF (receive stream done AND its ring drained, so a `tool_result` delivered before EOF still wins its wait, including via the wait's post-latch re-check), the tool bridge latches the connection disconnected, `executeStdioToolViaAgentProtocol` fails its parked wait with a typed `error.ClientDisconnected`, flags the run and sets its cancel token, and the run pump settles the run through the failure pair (settlement `agent_error` with code `tool_execution_error`, no trailing `agent_end` per §3.5, session marked `.error`) instead of a success `agent_result` — the process drains `hasActiveAgentRuns()` and exits instead of hanging until killed. Pending tool requests queued after EOF are dropped unpublished, and §13.2.7's other outcome is preserved: a provider-executing run keeps being pumped toward settlement. **Stale `tool_result` correlation for reused `tool_call_id`s** — in-flight bridge keys now record the published `tool_execute`'s `message_id` (a new execution supersedes any leaked key for the same id, closing the §13.4.4 stop-failure residual), and only a reply whose `in_reply_to` names it settles the wait; mismatched, absent, and unsolicited replies are discarded with the host's `unknown_envelope` runtime error. The TS SDK already replies through `buildAgentReplyEnvelope` (`in_reply_to` always set), so conforming clients are unaffected. Result CONSUMPTION is generation-bound too (§13.4.5): in-flight keys carry the publishing run's registration generation, and `popResult` settles only the waiting execution's own key — a stopped registration's late, preempted wait can neither consume the re-registered id's correctly-correlated result nor remove its key. Spec §13 and the `docs/oap-alignment.md` ledger updated to `[current]`/aligned for both gaps.

- Added server-side idle-session eviction to the agent protocol (spec §13.2.6 rule 6, #202): `AgentProtocolServer` now evicts sessions idle longer than a configurable TTL — default 30 minutes (`default_session_idle_ttl_ms`), adjustable via `AgentProtocolServer.Options.session_idle_ttl_ms` (`0` disables) and, for the stdio host, `MAKAI_AGENT_SESSION_IDLE_TTL_MS`. Idleness is measured from the session's last activity (inbound `agent_message` acceptance or `agent_status` poll, or server-side `agent_event`/`agent_result`/`agent_error` publication) on the monotonic clock (`compat.time.monotonicMillis` — wall-clock adjustments cannot distort eviction), sessions with in-flight runs (`.processing`) are never evicted, and settlement resets the idle clock. An evicted id is indistinguishable from a stopped one: the next `agent_message`/`agent_stop`/`agent_status` fails with `agent_not_found` and a fresh `agent_start` registers a new container; sequence bookkeeping and pending messages are removed with the session. The admission-vs-eviction race is closed server-side by construction (single-threaded pump serialization plus the in-flight exemption, with the stdio run pump's existing cancel-on-missing-session as backstop). The stdio host sweeps from its background pump (throttled to once per second, collecting expired sessions in a single traversal). Supersedes the pre-eviction state where session lifetime was 100% client-trusted (`agent_stop` or process exit, #199/#202).

Both makai emitters (the TS SDK's `buildAgentStartPayload` and the Zig serializer) send BOTH keys with the same value transitionally, and the server's dual-key parse prefers `session_id` while accepting the legacy `resume_session_id` permanently, so mixed-version clients and servers interoperate.

### Fixed

- Fixed real-provider streaming through the TS SDK failing with "invalid anthropic URL"-style errors: the protocol server now applies the canonical provider/API base URL defaults (env-overridable via `MAKAI_BASE_URL`/`ANTHROPIC_BASE_URL`/`OPENAI_BASE_URL`/`DEEPSEEK_BASE_URL`) in `stream_request` and `complete_request` handling, so the SDK's empty `base_url` model descriptors default correctly over the stdio protocol (#189).
- Fixed provider turn failures surfacing without detail in the agent event stream: the agent loop carries the provider's own error text (e.g. `auth_required`) verbatim in the error `AssistantMessage` instead of collapsing it to a Zig error name, and the stdio agent protocol serializes `error_message` on `turn_end` so SDK consumers can see what went wrong (#191).
- Fixed the agent protocol server's three spec §13 (v1.1) enforcement gaps (#204): (1) envelope/payload session-id agreement (§13.1) is now server-checked — `handleStart` (when the payload names an id), `handleMessage`, `handleStop`, and `handleStatus` compare the envelope and payload session ids first and reject a mismatch with a request-correlated `invalid_request` before any lookup, mutation, removal, or cancellation (previously all four keyed on the payload id alone, so a mismatched `agent_stop` could remove a session other than its routing identity while error replies traveled under the envelope id), and the stdio host's `validatedAgentStopSessionFromLine` treats a mismatched stop as unvalidated (no host-side run cancel or tool-bridge discard). (2) Echo-reply sequencing (§13.1) is resolved by decision (b): `session_info`/`pong`/`tool_list_response` permanently keep copying the request's inbound sequence as a correlation echo (option (a) — allocating them from the per-session counter — was rejected as a breaking change buying only cross-class monotonicity consumers are already forbidden to depend on); recorded as a permanent deviation in the OAP deviations ledger. (3) The stopped-id reuse race (§13.4.5) is closed server-side by registration generations: every registration stamps a monotonically increasing generation from one server-wide counter, an active run binds the generation it was admitted under, and stale runs (stopped, evicted, or re-registered id) are cancelled with every remaining publication discarded — no events, no settlement, no state mutation, so a stopped session's cancelled run can no longer settle — or mark `.error` — an id a new `agent_start` re-created, and the one-active-run check is generation-scoped so a listed stale run no longer fails the fresh registration's admitted run at start with `AgentBusy`. A stop cancels every listed run for the id (first-match cancellation left the current registration's run running through the stop), and stale tool requests are dropped at publication — the enqueuing agent thread does not observe its cancel token before enqueueing, so a request can land after the stop's bridge discard; requests carry their registration generation and `publishPendingToolRequests` validates it, so a stale `tool_execute` cannot be emitted into a re-registered id (codex review findings on #209). Frames the old registration already buffered downstream (outbox, pipe, stdout) still carry no generation on the wire and remain attributable to the re-created id until drained (§6.1). Spec §13.1/§13.2.6/§13.4.5 markers flipped to `[current]`; ledger provenance re-pinned (`#206` → `main` @ `bad82f0`, riding `#208` → `main` @ `9a3e5df`). The remaining #204 scope (EOF/disconnect cancellation, transactional publication, stale `tool_result` correlation, client sequence control — gaps 4–7) stays tracked in the ledger's P0 list.
- Fixed the TS SDK's two teardown guards required by spec §6.1/§13.4.2 (v1.1, #205): (1) `agent.run`/`agent.stream` stopped their session unconditionally on non-abort errors, including timeouts where no reply to the attempt's own `agent_start` was ever observed — on a caller-supplied `options.session_id` whose losing `agent_busy` reply was lost, that sequence-2 stop is ACCEPTED by the winning caller's fresh pre-message session and destroys it. Teardown now settles the tracker without sending (and without draining, which would eat the possible owner's frames) when the attempt observed no correlated reply to its start and the id was caller-supplied; a client-generated id keeps the unconditional stop (the one sufficient ownership evidence until #204's generation tokens), and any request-correlated start reply (`agent_started`, `nack`, `agent_error`) resolves the outcome and restores the normal stop. (2) `agent.run` terminated on the failure pair's first frame (`agent_event` carrying the terminal error) and sent stop-only, leaving the settlement `agent_error` — which carries no `in_reply_to` — queued: an immediate same-id follow-up parked it through its pre-acceptance window (post-#207 routing), claimed it as its own rejection on the first post-acceptance wait, and stopped the newly registered session. The failure-pair termination now tears down with a bounded quiescent drain (stop, then consume the settlement — ~50 ms idle window, 250 ms hard cap, exiting early only on the current stop's correlated `agent_stopped` reply: terminal-shaped frames that do not name this stop — the uncorrelated settlement `agent_error`, a stale `agent_stopped` replying to an earlier stop on the same id — keep draining, so no stale terminal reply survives to end a later run's drain early and leave its trailing frame for a subsequent run to misattribute, review finding on #208) before surfacing the error; `agent.stream()` already drained via its terminal teardown. Spec §6.1 and §13.4.2 markers flipped to `[current]`; the residual races (re-registration between correlated reply and stop, settlement arriving after the bounded drain) remain tracked in #204 per §13.4.5. The test fixture gained a faithful uncorrelated-output frame builder (`asyncFrame`), a one-shot failure-pair knob (`MAKAI_TEST_AGENT_FAILURE_PAIR_PATH`), and a start-reply suppression knob (`MAKAI_TEST_SUPPRESS_AGENT_START_RESPONSE`).
- Fixed the stdio transport routing frames to waiters by `stream_id`/`session_id` only, so two overlapping calls on one consumer-supplied agent session id competed for a single per-session route and misdelivered each other's replies (#201, spec §13.3.1): the duplicate start's `agent_busy` rejection was skip-discarded by the established call's pre-acceptance `in_reply_to` guard (the duplicate then surfaced a full `responseTimeoutMs` timeout), could be consumed by the established call after acceptance (tearing the legitimate session down), an uncorrelatedly accepted `agent_started` let the duplicate submit its message under a session it did not own, and a duplicate holding the read lock could consume and discard the established run's uncorrelated async output. `nextFrameForStream`/`nextFrameForSession` now accept a `correlate` wait option naming an outstanding request's `message_id` (plus `repliesOnly` for waits whose reply is outstanding): while such a wait is in flight, frames whose `in_reply_to` equals a registered request id are delivered to that request's waiter — promptly, via a poke, even while the waiter is queued behind the transport read lock — and never to a waiter merely sharing the route; a reply read during its owner's between-waits gap is parked with its `in_reply_to` recorded (claimable by the owner's next correlated wait, skipped by foreign correlated waiters, visible to uncorrelated waiters); a `repliesOnly` wait parks uncorrelated frames for the route owner instead of consuming them; frames without `in_reply_to` (or unmatched) keep stream/session-routed behavior, so the single-run fast path is unchanged, and re-routed frames never land in a queue the re-routing waiter itself dequeues from (no busy-spin; SDK-layer re-enqueueing remains a non-fix). An aborted correlated wait rejects without consuming its parked reply. The agent SDK correlates every frame wait of an attempt with its `agent_start` `message_id` until accepted (replies-only — a pre-acceptance duplicate owns nothing uncorrelated on the route), then with its `agent_message` `message_id`, and rejects a pre-acceptance `agent_started` whose `in_reply_to` names a different request (`run()` and `stream()`). The pre-existing SDK `in_reply_to` skips remain as defense for unmatched-reply delivery. Spec §13.3.1/§13.3.3 updated to `[current]`.
- Fixed release builds for macOS targets, which failed with `unable to find framework 'Security'. searched paths: none`: Zig skips its native SDK/framework detection when an explicit `-Dtarget=*-macos` is passed. `build.zig` now resolves the macOS SDK (`$SDKROOT` when set, otherwise `xcrun --show-sdk-path` on macOS hosts) and passes it as the build sysroot plus framework search path for the Security/CoreFoundation frameworks; the release workflow exports `SDKROOT` on the macOS jobs (#196).
- Fixed cross-compiling for Windows, which failed with `no field named 'HOME' in struct 'Io.Threaded.Environ.String'`: `compat.getEnvVarOwned(_, "HOME")` now resolves the home directory per target — POSIX keeps the memoized `HOME` environ scan, Windows resolves `USERPROFILE`, then `HOMEDRIVE` ++ `HOMEPATH` (a plain `HOME`, e.g. from Git Bash, still wins as a last resort) (#196).
- Fixed the TS SDK leaking a server-side agent session on every `agent.run`/`agent.stream` call (#199): the server removes a session only on `agent_stop`, which the SDK previously sent only on abort, so every completed or failed run left its session registered for the process lifetime and reusing a consumer-supplied `options.session_id` on the same client failed with `agent_busy`. The SDK now tears the session down on terminal frames (reason `"completed"`, carrying the tracked inbound sequence — the server rejects out-of-order stops) and on error and auth-retry-abandon paths (stop only — a background drain there would consume the frames of an immediate follow-up attempt), awaits a stop-reply-correlated frame drain on terminal and early-consumer-close exits so a follow-up run reusing the id starts clean (including past the trailing `agent_end` the server queues after `agent_result`), never stops a session whose id was rejected as `agent_busy` (it belongs to another live run), and skips stale tail frames from prior attempts on a reused id before its own `agent_start` is accepted. Spec §6.1 now defines session teardown ownership.
- Fixed `MakaiStdioClient.nextFrame` leaving timed-out waiters registered in `frameWaiters` (#199, found in review): `handleLine` resolves waiters FIFO without checking settlement, so a timed-out (already rejected) waiter entry caused the next incoming frame to be delivered to a dead promise and silently dropped — e.g. a follow-up agent run losing its `agent_started` and hanging until `responseTimeoutMs` after a prior run's terminal drain timed out once. Timed-out waiters are now removed from the queue when their timer fires. `nextFrameForSession` additionally accepts an optional `AbortSignal`: an aborted wait re-routes any frame it had dequeued back to the session buffer instead of consuming it, so an abandoned drain read cannot swallow a reused session id's next frame.

### Migration Notes

- The `agent_start` payload key rename (`resume_session_id` → `session_id`, #198/#211) is wire-compatible: the server accepts both keys permanently and both makai clients dual-emit during the transition. Raw-protocol integrations written against the old key keep working; migrate to `session_id` at your convenience (it is canonical when both keys are present).
- See [`docs/zig-0.16.0-downstream-migration.md`](docs/zig-0.16.0-downstream-migration.md) for downstream source migration guidance for Makai Zig consumers.

## [0.1.0] - 2026-09-05

### Added

- Initial release of Makai, a unified multi-provider AI streaming abstraction layer.
- **Zig core library**: lock-free event queues, type-safe tagged unions, streaming JSON parser, SSE parser, and provider implementations for Anthropic, OpenAI (Completions & Responses), Google (Generative AI & Vertex), Azure OpenAI, AWS Bedrock (stub), and Ollama.
- **Distributed protocol**: client-server wire protocol with envelope-based messaging, partial serialization/reconstruction, and in-process/stdio/SSE/WebSocket transports.
- **Agent loop**: tool execution lifecycle with distributed runtime support.
- **OAuth flows**: GitHub Copilot, Anthropic, Google, and OpenAI Codex OAuth with PKCE.
- **TypeScript SDK**: stdio client transport, high-level APIs for provider completions, streaming, agent runs, auth flows, and model discovery.
- **CLI**: `makai` binary with auth and stdio protocol support.
